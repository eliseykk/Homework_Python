# Вариант 3 — задания 5–10

В каждом task5.py–task10.py есть функции/классы и пример запуска внизу.
Открывай файлы по одному или запускай из терминала: `python task5.py` и т. д.
Условие `if __name__ == "__main__"` запускает пример при прямом запуске файла,
но не запускает его при импорте функций для проверки.

Для второй реализации задания 5 нужен numpy:

```bash
python -m pip install -r requirements.txt
```

Без numpy обычная реализация задания 5 остаётся доступна, а пример сообщает,
как установить библиотеку. Задания 6–10 используют только стандартную библиотеку.
Все текстовые файлы записаны в UTF-8.

## Задание 5 — аномалии

`find_anomalies(numbers, k)` и `find_anomalies_numpy(numbers, k)` возвращают
аномальные значения, сохраняя порядок и повторы исходного списка.
Среднее и стандартное отклонение в первом варианте считаются циклами.
Использовано стандартное отклонение по всей совокупности: сумма квадратов
отклонений делится на n, в numpy этому соответствует `ddof=0`.
Проверяется строгое превышение порога, как в условии: `> k * standard_deviation`.
Пустой список возвращает `[]`; у постоянного списка аномалий нет.
Отрицательный k и бесконечные значения отклоняются.

## Задание 6 — CSV продаж

`generate_sales(path, count=5000, seed=None)` записывает минимум 5000 корректных
продаж и дополнительные ошибочные строки. Товары берутся из заданного списка,
даты, количества и варианты ошибок выбираются через random.
`seed` позволяет получить повторяемые данные; для включённого sales.csv это 42.
В готовом sales.csv 5000 правильных и 100 ошибочных записей, плюс заголовок.

`analyze_sales(path)` читает CSV построчно, пропускает некорректные записи
и возвращает словарь с пятью требуемыми показателями и количеством записей.
Ошибка заголовка или доступа к файлу обрабатывается в примере запуска.
Некорректны, например: несуществующая дата, пустое название, нецелое или
неположительное количество, отрицательная/нечисловая/бесконечная цена,
отсутствующие значения или лишние поля.

В условии нет идентификатора чека: одна корректная строка принята за одну покупку.
Средняя стоимость покупки = общая выручка / количество корректных строк,
а не цена одной проданной единицы. При равенстве показателей выбирается первый
товар или день в порядке появления. При отсутствии продаж лидеры — None,
а пример выводит сообщение вместо статистики. Денежные вычисления — обычные
int/float; вывод округлён до двух знаков.

Пример читает sales.csv рядом со скриптом независимо от рабочей папки IDE.
Если его нет, генерирует заново. При наличии файл не перезаписывается.
Чтобы сгенерировать другой файл, вызови `generate_sales("other_sales.csv")`.

## Задание 7 — похожие строки

`find_similar_strings(strings)` возвращает `(строка1, строка2, различия)`.
Сравниваются только пары разных позиций списка с одинаковой длиной строк.
При равенстве расстояний остаётся первая найденная пара. Совпадающие строки
на разных позициях допустимы, расстояние между ними 0. Если пары нет — None.
Сортировка пар и библиотеки расстояний не используются.

## Задание 8 — retry

`@retry(3)` означает максимум три вызова всего, включая первоначальный.
Это число попыток, а не число дополнительных повторов.
Аргументы передаются исходной функции, результат возвращается сразу при успехе.
После последней неудачи исходное последнее исключение выбрасывается повторно.
functools.wraps сохраняет имя, документацию и другие метаданные.
Обрабатываются обычные Exception, а прерывание пользователем не подавляется.
Пример load_data случайно завершается ошибкой; допустим и успех с первой попытки,
и исчерпание всех попыток — это нормальные варианты демонстрации.

## Задание 9 — магазин

Product хранит name, price, quantity. Book добавляет автора, Electronic —
срок гарантии в месяцах, Food — дату окончания срока годности.
Store.add_product добавляет товар, find_product ищет без учёта регистра,
sell_product возвращает стоимость продажи и уменьшает остаток только при успехе.
Повторяющиеся названия отклоняются, неизвестный товар и нехватка остатков
вызывают ValueError. Одинаковый метод final_price вызывается полиморфно.

В условии не задана формула конечной цены. В этой реализации:
- Product: исходная цена;
- Book: скидка discount в процентах, по умолчанию 0;
- Electronic: исходная цена + явно заданная стоимость дополнительной гарантии
  warranty_price, по умолчанию 0; warranty_months сам по себе цену не повышает;
- Food: исходная цена; просроченный товар продавать нельзя.

День expiration_date считается последним допустимым днём продажи.
Проценты и надбавки в примере — демонстрационные параметры, не требования условия.

## Задание 10 — планировщик

Task — dataclass с полями name, priority, status, due_date.
Даты передаются строкой YYYY-MM-DD. Приоритет: 1 — низкий, 2 — обычный,
3 — высокий. Статусы: new, in_progress, done. Названия задач уникальны
без учёта регистра. Эти соглашения выбраны, потому что условие их не задаёт.

Методы TaskManager:
- add_task(task) — добавление;
- remove_task(name) — удаление;
- change_status(name, new_status) — смена статуса;
- find_task(name) — поиск, при отсутствии возвращает None;
- get_high_priority() — все задачи с приоритетом 3;
- get_overdue() — незавершённые задачи со сроком раньше сегодняшнего дня;
- save_tasks(path), load_tasks(path) — сохранение и загрузка JSON, возвращают bool.

При ошибке JSON, неверной структуре или значениях загрузка возвращает False,
сообщает об ошибке и сохраняет прежний список задач целиком. Успешная загрузка
заменяет список, а не добавляет дубликаты. Срок сегодня ещё не просрочен.

Декоратор operation_time пишет длительность основных операций в logging,
в том числе при исключении. При прямом запуске настроен файл task10.log рядом
со скриптом. При импорте настрой logging в своей программе, чтобы видеть INFO.
Пример создаёт tasks_demo.json; файл tasks.json с собственными данными не трогает.
Ошибки записи также обрабатываются. Для самостоятельной проверки повреждённого
JSON включён tasks_broken.json — загрузка должна вернуть False, не упав.

## Проверка

Перед упаковкой проверены все шесть скриптов и основные граничные случаи:
пустые и постоянные числовые списки, совпадение с numpy, неверные CSV-записи,
равные расстояния строк, исчерпание попыток, сохранение метаданных,
продажи сверх остатка, просрочка продуктов, JSON round-trip и повреждённый JSON.
